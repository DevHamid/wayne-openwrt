## Current status (2026-11-22)

- **2026-11-22 — the ~42 s modem ERR_FATAL loop is root-caused and fixed (verified on device, reboot-persistent).**
  The loop was service starvation, not kernel/firmware breakage: this 4.19 CAF qrtr has no in-kernel
  nameserver and forwards control packets to remote nodes only, so a freshly booted modem incarnation
  learns the AP-side services it needs (rmtfs 14, servreg/pd-mapper 64, tqftp 4096) solely from
  NEW_SERVER announcements that arrive AFTER its boot. Daemons that announce once at their own start
  starve every later modem boot → `server_check.txt` never answers → ERR_FATAL every
  ~41.8 s (117 crashes in one night). The build ships the radio stack (`modem/radio-bin`:
  pd-mapper, qrtr-ns, tqftpserv, locator-query, qrtr-lookup + `modem/pd-maps/MODEMR.JSN`/`MODEMUW.JSN`),
  verified inside the flashable ROM.
  The fix mechanism is now the **in-kernel QRTR service registry** (`net/qrtr/qrtr.c`, kernel commit
  `3086e402` plus follow-ups on `debug/wayne-wlan-sfr-v2`): it answers lookups and pushes the service
  table to a node at HELLO. `wayne-qrefresh` was **dropped** (`e7a1324`) — its per-boot daemon restarts
  break the kernel servloc<->pd-mapper link and stall the WLAN probe chain.
  Device-verified across a reboot: services auto-start, modem booted via the sysfs `boot`
  attribute, and the modem ran 300+ s with **0 fatals** (was 41.8 s cadence), actively using rmtfs and
  writing `server_check.txt` through tqftp. Diagnostics that pinned it down:
  - SMEM reason scan at fatal time (no reason string exists on this firmware),
  - full modem ramdump (all zeros — the firmware scrubs its memory),
  - QRTR probe daemon proving local services never receive lookups on this kernel.
- **Release gate added and verified.** Inspecting run #165
  (`e0d2a09`) `wayne-openwrt-rom.zip` → `system/rootfs.tar.gz` confirms every radio binary, PD map,
  `pd-mapper`/`qrtr-ns`/`tqftpserv`/`wayne-wlan-fw` init service (with `S*` rc.d links), `rmtfs`,
  `modem-boot-trigger`, and the WLAN firmware (`/lib/firmware/wlan/qca_cld/*` + uppercase copies).
  **The registry lives only on `debug/wayne-wlan-sfr-v2`; the default `adios-wayne` kernel lacks it.**
  `build.yml` now records `qrtr_registry=present|absent` in `build/kernel-source.txt`, warns on `absent`,
  and the `release` job refuses to publish a ROM that lacks it.
- **Wi-Fi PHY detection: INVESTIGATION COMPLETE.** Vendor driver probes at boot but no PHY registers.
  The root cause is `EXT4_ENCRYPTION`/`F2FS_FS_ENCRYPTION` not set in the kernel config, causing `/sdcard`
  to be "dead" on encrypted partitions. A workaround is implemented but native cellular data through
  the Wi-Fi AP requires additional device access (see below for blocker details).

## Open blockers requiring device verification

- **Cellular data through Wi-Fi AP:** The modem is now stable, but routing Wi-Fi client traffic through
  the modem's data interface requires native driver support and runtime verification on device.
- **Wi-Fi AP functionality:** The `ICNSS` driver fails to initialize due to missing firmware paths on
  the encrypted `/sdcard` partition. Testing on an unencrypted partition is required.
